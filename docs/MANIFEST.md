## 先读 verdict/ 而不是 gemma_verify/

`gemma_verify/verify_full.jsonl` 主键是 `(path, phrase)`，**分不清「判 NO」和「没审过」**。
`verdict/verdict_shard{0-7}.jsonl` 把它摊平成与 `clean_rec` 逐框对齐的形式，
2,894,189 行一一对应，按 `path` 关联、框按下标对齐，未审位置写 `null`：

```json
{"path": ".../001478524.jpg", "n_pair": 3, "n_audited": 2,
 "verdict": {"The text": ["YES"], "The characters": ["NO", null]}}
```

74,289,118 个框位里 30,303,579 个有 verdict（40.79%），43,985,539 个是 `null`。
用 `scripts/make_verdict_sidecar.py` 可从上面两份数据随时重建（纯 CPU，4 分钟）。

**与 `clean_rec` 严格逐行对齐**（已逐行核对 path，0 处错位），所以关联不用建索引：

```python
import json
for lc, lv in zip(open("clean_rec/clean_shard0.jsonl"),
                  open("verdict/verdict_shard0.jsonl")):
    r, v = json.loads(lc), json.loads(lv)
    assert r["path"] == v["path"]
    for phrase, boxes in (r.get("grounding") or {}).items():
        for bi, box in enumerate(boxes):
            verdict = v["verdict"][phrase][bi]   # "YES" / "NO" / None = 未审
```

### 审核覆盖多少 —— 先看这节再用

`s4_verify.py` 是**精度估计器**，不是标注器。它每图只取前 12 个短语
（`--max-boxes 12`）、每短语只取首框（`boxes[0]`），所以：

| | 数量 | 覆盖 |
|---|---|---|
| 图 | 2,868,984 / 2,894,189 | 99.13%（25205 张清洗后无短语） |
| 短语 | 30,303,579 / 56,007,139 | **54.1%** |
| (短语,框) 对 | 30,303,579 / 74,289,118 | **40.8%** |

这么设计是为了降估计方差：同一短语挂 5 个框若全审，它在均值里的权重就是别人的 5 倍；
同图短语高度相关，预算花在更多图上更划算。续传主键是 `(path, phrase)`，
文件结构上装不下同一短语的多个 verdict。

**算覆盖率别用文件头部当分母** —— 密度沿文件递增：`clean_shard0` 前 20000 行只有
9.14 短语/图，末尾是 29.02，全量均值 19.35。

YES 21,175,099（69.88%）/ NO 9,127,032（30.12%）/ ERROR 1,195 / TOO_SMALL 252 / UNPARSED 1。
**精度下界 69.88%**，与 1000 图抽样的 70.1% 只差 0.2pt —— 抽样没偏。

## 能做什么训练、不能做什么

### 先纠一个容易反过来的地方

「每短语只取首框」是**审核**的口径，不是**数据**的口径。`clean_rec` 里每个短语名下的
**全部**框都在（74,289,118 个框、25.67 框/图），转成 detect 式样本格式在数据层面没有障碍。
受限的是 verdict 只覆盖首框：

| 名下框数 | 短语数 | 占短语 | 对应框数 | 占框 | 其中被审短语 |
|---|---|---|---|---|---|
| 1 | 44,292,257 | 79.08% | 44,292,257 | 59.62% | 24,165,316 |
| 2 | 8,006,983 | 14.30% | 16,013,966 | 21.56% | 4,077,000 |
| 3 | 2,367,893 | 4.23% | 7,103,679 | 9.56% | 1,330,486 |
| 4 | 682,287 | 1.22% | 2,729,148 | 3.67% | 358,731 |
| 5+ | 657,719 | 1.17% | 4,150,068 | 5.59% | 372,046 |

多框短语 11,714,882 个（20.92% 的短语），名下 29,996,861 个框（40.38% 的框），
其中 **18,281,979 个非首框永远拿不到 verdict**。被审的 30,303,579 个短语里
6,138,263 个（20.26%）是多框短语，它们的 verdict 只描述首框那一个。

→ **verdict 不能用来在同一短语的多个框之间做取舍**，也不能当 NMS 之后的正确性判据。

### 更要紧的限制：没有 recall 保证（这条与 verdict 无关，补跑审核也解决不了）

- 框来自 Florence-2 对 dense caption 做短语定位。**caption 没点名的物体就没有框**，
  同一类别的多个实例是否被全部框出，没有任何机制保证。
- 短语是自由文本（`a woman`、`The characters`），不是固定类别词表，跨图没有类别对齐。

所以**未标注区域不能当负样本**。这是漏标（missing annotation），不是背景。

### 适合

- text-conditioned / referring 类任务：给定短语回归区域（phrase grounding、REC）——
  正好也是 verdict 覆盖的那个口径（短语 → 首框）
- region-text 对齐的对比学习、open-vocabulary grounding 的弱监督预训练
- 需要大量「区域-短语」弱配对的预热阶段

### 不适合，或必须额外处理

- 闭集 detection：没有类别词表，也没有 recall 保证
- 任何以 mAP / recall 为指标的**评测**：漏标会系统性压低分数，测出来的不是模型能力
- 拿 verdict 做多框取舍（见上）

真要做 detect 式训练，三条建议：

1. 用 partial-annotation / federated 类损失：只在已标注框上算正样本，未标注区域不进负样本
2. 样本加权只用首框 verdict，并且记住它只覆盖 40.79% 的框位；`null` 不是 `NO`
3. 多框短语建议只取首框（与 verdict 口径一致），或整条丢掉 ——
   别把非首框当「已验证」

## 用这批数据前必须知道的四件事

1. **69.88% 是下界不是真值**。判定器是 gemma4，与产出 caption 同模型族，存在确认偏误。
   人工裁决测出方向是**偏保守**：还原真实精度 **79.9%**（区间 69.5–86.0%），
   判定器自身准确率 84.6%。所以 69.88% 可以放心当下界用。

2. **小框那个 44.96% 不是标注错误率**。人工按同样分桶重新加权后，
   <0.5% 面积是 81.0%、0.5-2% 是 85.1%，与大框（80.0%）齐平 ——
   低分来自判定器在 20px 尺度看不清（小框误否率 60~64%，大框只 19%）。
   **不要按面积过滤小物体**，rec 档刻意不含 `--min-area`。详见 `docs/RESULT.md` 5.1。

3. **verdict 建议当置信度分层，别当硬过滤**。按 YES 筛精度能到 96.0%，
   但会误删约 2.4 短语/图 的正确标注；而且还有 59.2% 的框根本没有 verdict
   （在边车里是 `null`，别和 `"NO"` 混为一谈），硬过滤会把它们全部误伤成「未标注」。
   训练时给 YES 高权重、NO 低权重、`null` 按 (k, box_idx, 面积桶) 的先验加权更划算。

4. **69.88% 只描述「前 12 短语的首框」这个总体**。按短语在图内的序号拆开，
   精度从 k=0 的 82.44% 单调降到 k=11 的 62.89%（靠前是主体，靠后是细节），
   曲线已趋平，外推被截掉的 2570 万短语后**全短语精度约 65%**。
   1000 图基线 70.1%、人工裁决 79.9%、全量 69.88% 用的是同一套抽样规则，
   彼此可校准；但都不能外推到全部 7429 万对。
